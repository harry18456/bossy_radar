## Context

平台以 SSG 形式公開上市櫃公司的勞動與環境違規。資料流為 CLI（ETL）擷取 → 比對歸屬到公司 → 主庫（已連結）／ archive 庫（未連結）→ export 靜態 JSON → 前端消費。

公司歸屬比對目前有四層（統一編號、公司全名、分公司前綴、董事長），正典實作為 CompanyMatcher，但違規同步服務與 MOPS 爬蟲各自內聯重寫一份、且帶同樣 bug，僅環境裁罰服務委派 CompanyMatcher。

本 change 動工前已用 read-only 腳本對正式 DB 做 dry-run 量化各方案影響。現況規模：主庫勞動違規 11,889 筆、archive 167,435 筆；主庫環境 18,210、archive 223,544；MOPS 主庫 39,706。公司主檔 2,615 家（2,608 有統編、2,295 有董事長）。

## Goals / Non-Goals

**Goals:**

- 自然人／負責人違規在無佐證下不得自動連結到上市公司。
- 分公司前綴比對跨 run 確定，不因 DB 列順序改變歸屬。
- 三來源（勞動／環境／MOPS）共用單一比對實作，消除複製碼與 drift。
- 不誤殺既有正確連結，特別是「公司全名(負責人)」格式的 8,197 筆。
- 完成後以全量重抓重建資料，並以真實資料實證驗證（非僅單元測試或 mock）。

**Non-Goals:**

- 不以正規化／模糊比對救回 archive 漏接（實證：僅 0.1%，且會引入新誤掛）。
- 不補抽勞動違規統一編號（降級為查證；現況公司全名已足夠精確）。
- 不更動擴充套件層（extension-company-matching）的公司比對。
- 不納入公開 API 前的安全強化（屬另一 change）。
- 不重寫公司主檔資料品質問題（如臺灣土地銀行名稱缺後綴）；僅在比對層容錯。

## Decisions

### 決策一：分公司前綴比對改為確定性最長前綴與保守拒絕

dry-run 推翻了原始「白名單邊界字」構想，且進一步比對證明「黑名單」亦非必要且有害。實證：現況靠前綴連結的 8,197 筆，剩餘部分幾乎全是括號負責人（如 南山人壽保險股份有限公司(尹崇堯) → 5874、台灣電力股份有限公司(曾文生) → 9963；括號內皆為該公司董事長，連結正確）。

三方案 dry-run 對比（勞動違規，主庫現況 11,889）：

- 白名單邊界字：誤殺 8,197 筆正確連結（主庫剩 3,677），否決。
- 黑名單（剩餘以法人標識起始即拒）：誤殺 7 筆臺灣土地銀行型（主檔缺後綴，剩餘變「股份有限公司(…)」被誤拒），否決。
- 最長前綴 + 多候選拒絕（不加黑白名單、不剝後綴）：branch 誤殺 0 筆（抽樣明確確認），最佳。

採最後者：

- 蒐集所有「公司全名為輸入前綴且輸入更長」的候選。
- 取最長前綴的公司。括號負責人、廠區後綴、主檔缺後綴（如臺灣土地銀行其主檔名本身即為輸入前綴）等情形，皆因「公司全名為前綴」自然涵蓋，無需特別處理或剝後綴。
- 多個不同公司代號並列最長前綴 → 拒絕、不猜。

確定性：最長前綴唯一即確定、多候選即拒絕，結果與候選清單順序無關，因此跨 run／跨 DB 重建不變。dry-run 顯示「同時是兩家以上公司前綴」的違規目前為 0 筆（非確定性為理論風險、當前零實例），但仍實作以防未來資料變動。

替代方案：白名單邊界字（誤殺 8,197 筆）、黑名單（誤殺 7 筆臺灣土地銀行型）、維持「第一個命中」（非確定性），均否決。

### 決策二：停用第四層董事長純人名自動連結

實證：現況靠董事長連結且為純人名的違規僅 13 個人名／15 筆（如 違規名稱「劉正忠」 → 4171 瑞基海洋，劉正忠為其董事長；「陳國寶」 → 2354 鴻準，陳國寶為其董事長）。純人名無公司全名背書，無法分辨「該公司違規只填了負責人」或「另一同名自然人的違規」，自動連結即為無佐證的不實陳述風險。

改為：移除第四層董事長自動連結；純人名連不上即歸 archive。代價僅 15 筆（漏接無害），消除誹謗級誤掛。環境裁罰服務經 CompanyMatcher 也適用此規則（其以統編／名稱為主，董事長 fallback 命中率低，停用更安全）。

替代方案：要求統編佐證才連（弱佐證，但勞動違規來源未存統編、且事業單位統編未入清單時仍可能誤掛，否決為預設）；改人工複核佇列（需額外機制，超出本 change 範圍）。

### 決策三：三來源比對收斂為單一 CompanyMatcher 並新增公司代號層

違規同步服務與 MOPS 爬蟲移除內聯比對、改委派 CompanyMatcher。CompanyMatcher 新增「公司代號精確比對」層供 MOPS（其原始資料帶上市櫃代號，最可靠）。優先序：公司代號 → 統一編號 → 公司全名（含簡稱）→ 分公司前綴（決策一）；董事長層移除（決策二）。

dry-run 確認收斂安全：MOPS 0 筆受影響；環境在最長前綴方案下由白名單版本的 471 筆誤殺降為僅 1 筆（福豐盛投資股份有限公司，現況連 5487 但其 tax_id 不在主檔、名稱亦非任何上市公司前綴，疑為現況誤掛、被新邏輯正確擋下）；臺灣土地銀行分公司因主檔名為前綴而正確保留。

### 決策四：全量重抓重建 + re-attribution 清理

原假設「全量重抓即重建」，但實證推翻：sync 採 upsert（ON CONFLICT DO UPDATE），不 DELETE。既有 main 的舊誤掛（如純人名「劉正忠」→4171）在重抓時，新比對走 archive 路徑、不碰 main 的舊列，導致舊誤掛殘留於 main（重抓 sync-companies + sync-violations 後 analyze 實測 main 仍殘留 16 筆）。

故流程修正為：備份 → 全量重抓（驗證 sync flow 並以新邏輯寫入新資料）→ re-attribution 清理（腳本 backend/scripts/reattribute_cleanup.py：對 main 每筆以新 matcher 重算，無匹配者歸 archive 並自 main 移除、改連者更新 company_code，冪等）→ 實證 analyze main drop 為 0。

註：本清理聚焦「誤掛」（5b 範圍）；來源已移除的 stale 違規屬資料新鮮度議題，不在本 change。

### 決策五：不以正規化或模糊比對救回 archive 漏接

dry-run：對 archive 勞動違規做正規化（臺／台統一、去括號、去法人後綴）後僅 198 筆／73 個公司名能命中主檔（佔 archive 0.1%），且其中混入新誤掛——例如 廣達有限公司(曾坤升) → 廣達電腦 2382，但曾坤升並非廣達電腦董事長，證明該「廣達有限公司」並非廣達電腦。大量「某某有限公司」（非上市的另一類法人）去後綴後碰巧等於上市「某某股份有限公司」簡稱，規則無法分辨。為 0.1% 漏接而引入新的妨害名譽誤掛，得不償失，故維持「無佐證不連結」。

## Implementation Contract

**可觀察行為**：ETL 同步後，勞動／環境／MOPS 三來源的公司歸屬一致由 CompanyMatcher 決定：

- 輸入為「公司全名(負責人)」或「公司全名+廠區」→ 連結到該公司全名對應的公司代號。
- 輸入為純人名（無公司全名前綴）→ 不連結，存入 archive。
- 輸入前綴同時符合多家不同公司 → 不連結，存入 archive。
- 同一輸入在不同次同步、不同 DB 列順序下，歸屬結果一致。

**介面／資料形狀**：CompanyMatcher 提供綜合比對方法，優先序為 公司代號 → 統一編號 → 公司全名（含簡稱）→ 分公司前綴；不再有董事長自動連結。違規同步服務與 MOPS 爬蟲呼叫此單一實作，移除各自的內聯比對函式（含其內聯的 chairman 與第一個命中 branch 邏輯）。回傳為公司代號字串或無匹配（None）。

**失敗模式**：任何層級無把握即回傳無匹配（None）→ 該筆寫入 archive（保守、可觀察、非靜默吞錯）。

**驗收（須實證，不接受僅單元測試或 mock 通過）**：

- table-driven 單元測試涵蓋下方邊界案例，pytest 全綠、ruff 通過。
- 對正式 DB 的備份跑 analyze_attribution_impact.py，數字須符合：勞動主庫保留 11,874、移 archive 15（全為董事長純人名）；環境移 archive 1（福豐盛投資，疑似誤掛）；MOPS 0。
- 全量重抓後抽樣：純人名（如「劉正忠」）位於 archive、公司全名(負責人) 正確連結、無新誤掛、臺灣土地銀行型未被誤殺。

**In scope**：CompanyMatcher 比對邏輯、違規同步服務與 MOPS 爬蟲的收斂、前端資料比對說明頁、分析腳本。
**Out of scope**：救回漏接、補統編、公司主檔資料修正、擴充套件比對、公開 API 強化。

邊界案例（TDD 對照）：

| 輸入 company_name | tax_id / raw_code | 期望結果 | 理由 |
| --- | --- | --- | --- |
| 公司全名後接(董事長) | 無 | 連該公司 | 括號後綴，最長前綴自然涵蓋 |
| 公司全名後接廠區 | 無 | 連該公司 | 廠區後綴，最長前綴自然涵蓋 |
| 純人名（如劉正忠） | 無 | archive | 不為任何公司全名前綴，且董事長層已移除 |
| 臺灣土地銀行股份有限公司(何英明) | 無 | 連 5857 | 主檔名「臺灣土地銀行」本身即為前綴 |
| 廣達有限公司(曾坤升) | 無 | archive | 不為「廣達電腦股份有限公司」前綴，不模糊救回 |
| 同時為兩家公司前綴 | 無 | archive | 多候選並列最長前綴，拒絕 |
| 同一輸入跨兩次比對 | 無 | 結果一致 | 確定性 |
| MOPS 原始代號命中 | 有代號 | 連該代號 | 公司代號層 |

## Risks / Trade-offs

- [免責聲明無法替代正確性] → 但書是對使用者的契約限制，對被誤掛公司（第三方）的妨害名譽侵權無效；唯一有效抗辯是合理查證／相當理由確信為真。本 change 將無根據猜測改為有根據才陳述，實質提升查證強度；archive（不陳述）使侵權構成要件不成立。
- [最長前綴方案的理論邊界] → dry-run 實證 branch 誤殺 0 筆（含臺灣土地銀行型，因主檔名即為前綴而正確連結）；理論上「公司全名後直接接另一完整法人名」會連到前綴公司，但真實資料零實例，且多家並列最長前綴時已拒絕。
- [archive 約 16 萬筆漏接未救回] → 實證可救回僅 0.1% 且會引入新誤掛；漏接公司多半另有正確寫法違規已連結，公司頁不致空白；屬可接受取捨。
- [全量重抓覆蓋現有 DB] → 動資料前備份 bossy_radar.db 與 archive.db；重抓後以 analyze 腳本對比加抽樣，異常則還原備份。
- [重抓後主庫筆數不暴增的預期落差] → 事前說明：archive 仍約 16 萬為正常（個人／未上市／小商號），非 bug。

## Migration Plan

1. 備份 bossy_radar.db、archive.db。
2. TDD 實作 CompanyMatcher（決策一至三），先寫失敗測試再實作。
3. 收斂違規同步服務、MOPS 爬蟲；環境服務加回歸測試。
4. 實證一：對備份 DB 跑 analyze_attribution_impact.py，確認數字符合預測。
5. 更新前端資料比對說明頁與 DATA.md。
6. 全量重抓：依序 sync-companies、sync-violations、sync-env、sync-mops（打真實來源，已授權），驗 exit code。
7. 實證二：重抓後再跑 analyze 腳本加抽樣（純人名在 archive、無新誤掛、土銀型未誤殺）。
8. export → 前端 generate → 部署 → production console 零錯誤。
9. 回滾：任一實證失敗即還原 DB 備份、git revert 程式碼。
